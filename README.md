# SOAR-Bot
### n8n 기반 보안 이벤트 판정 및 다중 채널 알림 자동화

보안 이벤트를 Webhook으로 수신하고, 위험 수준에 따라 허용·거부를 판정한 뒤 Slack, Discord, Telegram으로 알림을 전송하는 프로젝트입니다.

판정 결과를 웹 서버에 저장하여 보안 대시보드에서 이벤트 이력과 통계를 확인할 수 있도록 구성했습니다.

> 이 프로젝트의 `deny`는 워크플로우의 거부 판정을 의미합니다. 실제 방화벽의 IP 차단 여부와는 별개입니다.

## 1. 프로젝트 목적

- 보안 이벤트의 수신부터 판정, 알림, 기록까지 자동화
- 동일한 판정 결과를 여러 메신저에서 확인
- 대시보드를 통한 보안 이벤트 이력 및 현황 조회
- n8n의 조건 분기와 외부 API 연동 실습

## 2. 사용 기술

| 기술 | 용도 |
|---|---|
| n8n | 워크플로우 구성 및 실행 |
| Webhook | 보안 이벤트 수신 |
| Code 노드 | 이벤트 정보 처리 및 판정 |
| IF 노드 | 허용·거부 결과에 따른 분기 |
| HTTP Request | 메신저 알림 전송 및 이벤트 저장 |
| Slack Incoming Webhook | Slack 채널 알림 |
| Discord Webhook | Discord 채널 알림 |
| Telegram Bot API | Telegram 봇 알림 |
| 웹 대시보드 | 저장된 이벤트와 통계 조회 |

## 3. 전체 처리 흐름

```text
보안 이벤트 수신
       │
       ▼
    Webhook
       │
       ▼
이벤트 분석 및 위험도 판정
       │
       ▼
  허용 / 거부 분기
       │
       ▼
  결과 메시지 생성
       │
       ├── Slack 알림
       ├── Discord 알림
       ├── Telegram 알림
       └── 웹 서버에 이벤트 저장
                    │
                    ▼
             보안 대시보드 조회
```

### n8n 워크플로우

Webhook으로 수신한 데이터를 판정 노드에서 처리하고, IF 노드에서 허용·거부로 분기합니다. 각 분기에서 생성한 메시지와 이벤트 정보를 외부 서비스로 전달합니다.

## 4. 주요 기능

### 보안 이벤트 판정

이벤트의 `level`을 기준으로 심각도와 처리 결과를 구분합니다.

| 이벤트 수준 | 심각도 | 판정 |
|---|---|---|
| 10 이상 | High | 거부(`deny`) |
| 7 이상 10 미만 | Medium | 허용(`allow`) |
| 7 미만 | Low | 허용(`allow`) |

첨부된 테스트 결과에서는 `level 10` 이벤트의 거부와 `level 5` 이벤트의 허용을 확인했습니다.

### 다중 채널 알림

판정 결과를 Slack, Discord, Telegram으로 전송합니다.

알림 예시:

```text
🚫 192.168.0.10 | level 10 (rule 5712) → deny | High | 서효상
✅ 192.168.0.15 → Low
```

### 이벤트 저장 및 조회

판정된 이벤트를 웹 서버에 저장하고 대시보드에서 확인합니다.

- 전체 이벤트 수
- 허용 및 거부 이벤트 수
- 최다 거부 IP
- 거부 상위 IP
- 최근 이벤트 목록
- 학생별 조회 및 허용·거부 필터

## 6. 대시보드 연동 API

| 메서드 | 경로 | 역할 |
|---|---|---|
| POST | `/api/security/events` | 판정된 이벤트 저장 |
| GET | `/api/security/events` | 이벤트 목록 조회 |
| GET | `/api/security/events/summary` | 이벤트 통계 조회 |

n8n에서 이벤트를 저장하면 대시보드가 목록 및 통계 API를 통해 해당 기록을 조회합니다.

## 7. 트러블슈팅 및 확인 사항

### Code 노드 구문 오류

개발 과정에서 Code 노드 실행 시 다음 오류가 발생했습니다.

```text
Unexpected identifier '$'
SyntaxError
```

이 오류는 코드 구문과 실행 환경을 점검해야 하는 사례로 기록했습니다. 스크린샷만으로 정확한 원인이나 수정 내용을 확정할 수는 없습니다.

점검 항목:

- 선택한 언어와 작성한 코드의 일치 여부
- 입력 데이터 접근 방식
- 문자열의 따옴표 및 백틱 사용
- n8n 표현식과 일반 코드의 구분

### 알림에 표현식이 그대로 출력되는 현상

Slack의 초기 테스트 메시지에는 다음 표현식이 실제 값으로 변환되지 않고 출력된 기록이 있습니다.

```text
{{ $json.src_ip }} → {{ $json.severity }}
```

이 경우 메시지 필드의 Expression 설정과 입력 데이터 필드명을 확인해야 합니다. 이후 메시지에서는 `192.168.0.15 → Low`로 실제 값이 출력된 것을 확인했습니다.

### 대시보드 집계 표시 확인 필요

대시보드에는 거부 이벤트가 2건 표시되지만, 거부 상위 IP의 횟수는 `0회`로 나타납니다. 이벤트 집계 값과 화면의 횟수 표시가 일치하는지 추가 점검이 필요합니다.

## 9. 향후 개선 방향

- 거부 상위 IP의 횟수 집계 및 표시 보완
- 중복 이벤트 처리 기준 추가
- 외부 API 전송 실패 시 재시도 및 실패 기록
- 날짜와 심각도에 따른 검색 기능
- 입력 데이터 검증 및 Webhook 인증
- 실제 차단 장비와 연동할 경우 승인 및 차단 해제 절차 추가

## 10. 프로젝트를 통해 배운 점

- n8n으로 이벤트 수신부터 알림과 저장까지 연결하는 방법
- 조건 분기를 활용한 보안 이벤트 분류
- 메신저별 API 요청 형식의 차이
- 표현식과 실제 데이터 매핑의 중요성
- 메시지 전송 결과와 대시보드 기록을 함께 검증하는 방법
